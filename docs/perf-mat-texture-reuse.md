PR #58 accepted the allocation design at `f8dccfee8b94015690a891d20c02d99479fda2b4` after all six final-head checks. These runs certify their exact 0.7 sources, not the new 0.8 candidate.

Core's [allocation planner](../crates/mixture-core/src/compiler/allocation.rs) runs after slicing and stable pass ordering. Every logical output has a last consumer; requested output aliases stay pinned to the pass-count sentinel. A producer reuses the lowest-numbered complete-descriptor-compatible slot only when its previous occupant's last consumer strictly precedes this pass. Equal-pass input/output overlap is forbidden. All descriptors remain rgba16float; Scalar, Color and Normal slots are separate. External RGBA8 inputs are not pooled.

The immutable plan's `allocation()` exposes slot descriptors, logical-resource-to-slot mapping and last uses. `texture_count` / `textureCount` counts physical pass slots; `logical_texture_bytes` / `logicalTextureBytes` counts all logical results; `texture_bytes` / `textureBytes` counts actual pass slots. The unchanged uniform, upload and sequential readback rules produce conservative peak/cumulative budgets. The default 512 MiB ceiling is unchanged.

wgpu's [resource owner](../crates/mixture-wgpu/src/resources.rs) creates each physical texture once per call, builds each pass's bindings from logical mappings, and retains slots until readback/cleanup. It keeps distinct compute passes and the same shaders. `AllocationReport.texture_count` includes physical pass slots plus independent uploaded images. `reused_bytes` records avoided pass-result allocation bytes, not memory retained across calls. Bind groups clear before each unique texture is destroyed; success reports zero live bytes and balanced release accounting. Driver overhead, CPU pixels and immediate physical VRAM reclamation are outside these counters.

Plan/hash version 3, browser API schema 3 and graph CLI report schema 3 make the new memory meaning explicit. `.mix` and `.mixpack` remain v1; doctor, fixed checker and asset envelopes remain schema 1; `validate` remains unversioned. Recompile `.mix` plus requests and invalidate stored plan/hash caches; there is no plan deserializer or automatic source migration. Thin TypeScript projections include typed allocation arrays and bigint estimates. Source/lock peer versions move together; npm publication is not performed.

[Core schedule tests](../crates/mixture-core/tests/allocation.rs) include explicit chain/diamond/repeated-input/alias/default/sliced expectations and the frozen 2K material's fourteen-slot map, inclusive budget boundary and one-byte-under rejection. GPU probes exercise multiple dimensions, pinned early results, output aliases, repeat accounting, owned pixels after destruction and fault-injected same-pass overlap cleanup/retry. Existing upload/readback-failure tests remain required.

The eleven original material hashes use a finite, exact [v2-to-v3 allocation record](./plan-v3-migration.json), chained to the unchanged v1-to-v2 record. `node scripts/verify-plan-v3.mjs` verifies the typed v3 hash and reconstructs the exact old v2 hash by removing only allocation metadata and restoring retain-all estimates; kernels, passes, outputs and numeric tokens cannot change. Set `MIXTURE_CLI` to the freshly built CLI if it is outside `target/debug`. The historical v2 verifier is used with its original v2 runtime. Old plan snapshots remain; new v3 snapshots explicitly replace current test expectations. No pixel golden is reset.

The candidate [public browser test](../examples/browser-consumer/tests/reuse.spec.mjs) executes four painted-metal requests (odd seeded size, intact endpoint, default 1K and default 2K), repeated/sliced outputs, typed v3 allocation metadata and pixels after destruction. Candidate consumption now requires twenty tests; exact published-registry consumption still requires thirteen. Run `node scripts/browser-runtime/check-reuse.mjs <candidate-qualification> <fresh-output>` after a clean candidate build/consumption. It runs the [independent Rust test](../examples/native-consumer/tests/texture_reuse.rs) in release mode, checks twenty channel comparisons at the frozen ≤1/255 gate, identical plan/allocation metadata, package roundtrips, physical counters and matched-adapter cold/five-warm-sample timing budgets from the frozen MAT-02 plan. Both Native and browser retain PNGs and reports. Existing upload/package qualification remains required. The Chromium job includes this check without removing any existing gate.

For a standalone Native probe, set `MIXTURE_REUSE_ROOT` to the checkout, `MIXTURE_REUSE_EVIDENCE` to a fresh directory whose parent exists, and explicit `MIXTURE_GPU_BACKEND` / `MIXTURE_GPU_SOFTWARE`; run `cargo test --release --locked --all-features --manifest-path examples/native-consumer/Cargo.toml --target-dir target/native-consumer --test texture_reuse -- --ignored --nocapture`. Optionally set `MIXTURE_REUSE_BROWSER` to the comparison directory containing `reuse-browser.json` and its PNGs. `MIXTURE_REUSE_BEFORE` selects the retained pre-reuse directory only for the measured GT 1030 Vulkan adapter and requires exact decoded 1K bytes. Failed timing/parity results remain in `native.json`; unknown adapters have an unqualified timing result, and the comparison wrapper requires a matched passing budget.

`cargo xtask trace-2k` keeps its existing three-material workload, ranking and 512 MiB gate; its new `m3-pooled-2k-allocation-trace` kind verifies physical-slot counts, expected reuse, estimate agreement and cleanup. This regression is separate from painted-metal qualification. Required completion includes source-bound clean-candidate 1K exact before/after pixels, actual 2K five-channel execution, frozen cold/warm timings, Native/browser and package consumption, original/explicit-noise-v2 material matrices, all six CI checks and post-merge checks.
