# MAT-04 — 启动可复用配方

[English](./mat-04-reusable-recipes.md) | 简体中文

**当前状态：** 已集成功能、已发布版本及硬件验收范围见[发布状态](./release.zh-CN.md)。较早的带日期记录描述其当时的检查点。

2026-10-12，维护者将 MAT-04 启动为唯一的当前增量。本入口文档记录测得的重复、第一个消费者结果、MAT-04a 契约必须回答的问题及工作项顺序。它不选择格式、语法、节点、crate 或版本，也不修改代码、fixture、golden 或 schema。在已接受的契约和 ADR 作出决定前，`.mix v1`、`.mixpack v1` 及计划／API v3 保持不变。

## 第一个消费者结果

作者只写一次共享配方，并在至少两个独立的已验收材质图中使用。配方具有类型化输入和输出、可驱动多个内部参数的公开参数接口、显式种子处理及版本。实例化该配方的父图，经现有 Core 编译器和唯一的 wgpu 执行器，渲染出与等价的手工展开图完全相同的像素。Native 与浏览器调用方显式提供全部依赖，不做路径、URL 或注册表查找。一个小型预设语料只设置接口值。

## 测得的入口问题

所有计数来自 main 上已验收的 fixture，可直接从所引文件读出。

| 材质族 | 节点／边／暴露参数 | `.mix v1` 无法表达的重复 |
|---|---|---|
| [brick-paving](../fixtures/materials/brick-paving/material.mix)（MAT-01） | 11 / 12 / 24 | 三个 `brick-pattern@1` 实例（height、color、mask）重复七个布局控制；24 个暴露绑定中有 21 个是这些副本。[controls.json](../fixtures/materials/brick-paving/controls.json) 在调用方代码中把每个概念控制扇出到三个绑定。 |
| [woven-fabric](../fixtures/materials/woven-fabric/material.mix)（MAT-03 r3） | 22 / 26 / 33 | 三个 `weave-pattern@2` 实例（warp-share、coverage、height）重复七个控制；33 个暴露绑定中有 21 个是副本。[woven-fabric-requests.mjs](../scripts/woven-fabric-requests.mjs) 保持它们相等，并由颜色和 `detailAmount` 推导 `warpDark`／`weftDark`。经纱和纬纱各自重复同一条 noise → transform → levels → gradient-map 纹理链。 |
| [painted-metal](../fixtures/materials/painted-metal/material.mix)（MAT-02 r2） | 24 / 34 / 21 | 锈层通过四个并行混合节点，把同一遮罩施加到 baseColor、roughness、height 和 metallic。 |

由此得到两个具体缺口：

1. **参数扇出。** v1 暴露参数只指向一个节点参数，且目标必须唯一，因此一个概念控制无法驱动多个节点。砖块和机织物在调用方代码中绕过这一点；每个新消费者都必须重新实现该映射。机织物已占用默认 64 个暴露参数上限中的 33 个。
2. **跨族共享的分层合成。** 砖块（砂浆／砖）、机织物（底布／纱线）和彩漆金属（漆／锈）都构建遮罩控制的两层表面：同一遮罩通过 `blend` 在两种颜色间选择，并通过 `scalar-mask-blend` 在两个粗糙度间选择；彩漆金属还将其扩展到 height 和 metallic。每个图都用不同的节点 ID 和绑定手工重建该结构。

这是采用带类型接口和参数映射的可复用配方契约的证据，**不是**通用表达式的证据：机织物的推导暗色是调用方算术，用户脚本仍按[路线图](../ROADMAP.zh-CN.md#材质能力路线图--分阶段交付)排除。它也不表明需要嵌套配方、配方市场或自动迁移。

## MAT-04a 契约须回答的问题

在任何实现 PR 之前，MAT-04a 契约及其 ADR 必须逐项回答：

1. **承载与版本。** 配方定义放在何处（内联在父文档中、由调用方单独提供的文档，或两者），以及由哪个文档版本承载。`.mix v1` 拒绝未知字段，必须保持其确切含义；旧运行时必须以结构化错误拒绝新文档，绝不重新解释。像 M6B-02 一样，以测得的字节大小和验证成本比较候选方案。
2. **身份与依赖闭包。** 配方引用指明显式身份和版本。调用方以字节形式提供完整依赖集合；Core 验证闭包，拒绝缺失、多余版本和重复定义，绝不搜索文件系统或网络。必须规定内容完整性，以及定义身份如何进入计划哈希。
3. **类型化接口。** 输入和输出使用现有端口种类并精确匹配，不做隐式转换。规定哪些接口端口可选及其默认值。
4. **参数映射。** 一个接口参数可驱动多个类型和范围兼容的内部参数。规定范围求交、默认值、父图可暴露哪些接口参数，以及现有暴露参数唯一性和 64 个绑定上限如何适用。映射是直接赋值；算术表达式需要另行证明的案例。
5. **种子。** 每个随机节点仍需显式种子。决定实例种子如何提供，同一配方的两个实例能否共享或必须区分种子，且不得有改变现有像素的隐藏推导。
6. **展开与计划身份。** Core 在编译前把实例展开为现有节点图，因此 RenderPlan、wgpu kernel 和像素无需新的执行语义。展开后的节点 ID 必须确定且可诊断。父图与其手工展开等价图必须编译出相同的 pass 和像素；决定二者计划哈希相等还是有意不同。
7. **上限。** 规定嵌套深度（或在第一切片中禁止嵌套），并对展开图及每个源文档应用节点／边／参数上限。展开必须在任何大分配之前保持有界。
8. **诊断。** 对配方循环、缺失或不支持的版本、接口类型不匹配、未知或重复的接口参数及无效映射给出可操作的结构化错误，并使用共享诊断排序。
9. **包兼容性。** `.mixpack v1` 只容纳一个 `material.mix`。决定配方闭包现在是否随包传递（这需要按 ADR 0008 规则引入新包版本），还是先作为松散输入功能。无论如何，包 v1 字节保持其含义。
10. **归属。** Core 负责解码、验证、展开和哈希；`mixture-asset` 负责任何包变更；除非契约证明需要，wgpu 不变；CLI、WASM 和 JS 保持轻薄。没有实际边界不新增 crate。

## 维护者对 MAT-04a 的方向（2026-10-12）

维护者为契约选定了三个方向；它们收窄问题 1、7 和 9，但尚不是契约：

- **独立配方文档。** 配方是具有显式身份和版本的独立文档，由调用方以字节形式提供。父图从新的文档版本引用它；`.mix v1` 保持其确切含义。第一切片不包含内联定义。
- **仅松散输入。** `.mixpack v1` 不变，本增量中配方闭包不随包传递。以后的包版本需要自己的已证明分发案例。
- **禁止嵌套。** 配方不能实例化另一个配方；展开深度恰为一层。嵌套需要以后的实测案例。

## 停止与范围规则

如果契约需要第二个执行器、改变任何现有 `.mix v1` 文档或节点的含义，或需要放宽已接受的材质门槛，则停止。配方提取不得改变已验收的砖块、彩漆金属或机织物矩阵的像素；等价性须经测量，而非假定。排除：隐式文件系统或网络查找、配方注册表或市场、用户脚本或参数表达式、自动文档迁移、文档中的编辑器布局或缩略图、Studio 变更及发布。上述任一项都需要自己的已证明案例和决定。
