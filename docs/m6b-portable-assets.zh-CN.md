## 首个消费者目标

**M6B-03 更新：** [共享 CPU codec](./m6b-03-cpu-assets.zh-CN.md)现已实现，提供确定性写入、借用/拥有装载和 Core 准备。下面的启动记录保留历史；CLI/浏览器包 API 尚待 M6B-04，像素验收尚待 M6B-05。

**M6B-02 历史更新：** [格式/所有权/预算选择](./m6b-package-format.zh-CN.md)及 [ADR 0008](./decisions/0008-portable-assets.zh-CN.md)现选定规范未压缩 USTAR、独立可选 Rust CPU codec 边界与明确缓冲上限，替代方案测量及畸形输入 fixture 已留存。下一实现切片为 M6B-03，装载器尚未实现；上文启动状态保留 M6B-01 历史描述。

调用方能把包含一份不变的 `.mix v1` 文档及其现有 `rgba8-linear` 高度资源的**单个离线资产**搬到另一个目录或机器。Native 公共消费者与浏览器公共包能在无 GPU 时检查它，随后准备相同的内容绑定计划，通过现有 wgpu 路径渲染。接收方提供字节和渲染选项，不需要作者机器路径、伴随文件搜索、URL、服务账号或网络解析。CLI 文件处理是相同装载器的适配层，不另写一套实现。

使用现有 `image-input` / `scalar-blend` 高度法线 fixture、一张 1024×1024 图、0/0.25/0.5/1 四种权重以及小型非对称图像对照。不新增节点、图像语义、采样器、分辨率转换、图语法或像素 kernel。范围独立于 NUM-01：起始基线为 main `c2a08e14be9991d75df24e0f045d842d8db4b570` / 0.3.0，不是未合并的 0.4 噪声分支。后续验收须标识精确集成节点版本，打包绝不静默迁移它们。

## 实测进入问题

[留存测量](./evidence/m6b-01/measurement.json)由 [CPU-only 探针](../scripts/probe-portable-assets.mjs)复现：

- 1,157 字节的 `.mix` 验证通过，无资源依赖的 `baseColor` 切片可成功编译。
- 请求 height/normal 时，在 compile 阶段以资源 ID `heightSource` 返回 `MIX_RESOURCE_MISSING`，退出码 2。把尺寸正确的原始图像放到复制后的文档旁边仍出现相同结构化失败。当前 CLI 选项没有资源绑定装载器。SDK 支持调用方绑定，但传输由应用自行实现。
- 1K 紧密 RGBA8 图像为 4,194,304 字节，源码加像素在两个文件中共 4,195,461 字节，仍需外部提供 ID/格式/尺寸/stride 知识。
- 刻意未定义为公共格式的 JSON/base64 表示为 5,593,949 字节，base64 载荷本身为 5,592,408 字节，约膨胀 33.3%。这是字节计数，不是装载耗时、峰值内存或网络性能测量。

这证明需要可移植绑定与内容完整性契约，**不证明**自定义二进制格式、压缩或缓存是必要的。目录加 manifest 仍是可行的多文件基线，将这种 manifest 放入标准归档也是对照候选。应用已经可以自行实现传输；M6-B 提供共享生产者契约，避免接收方反复构建互不兼容的装载器。

从记录的基线复现，或向探针传入另行构建的基线 CLI：

```sh
cargo build --locked -p mixture-cli
node scripts/probe-portable-assets.mjs tmp/m6b-entry-run
```

目标目录必须全新。探针不获取 GPU、不渲染像素、不覆盖 fixture，也不声称实现生产格式；合成 RGBA 字节只是输入数据。它有意断言基线当前缺少绑定的行为；装载器实现后，应以基线 CLI 复现历史证据，而非改写预期失败。

## M6B-02 必须明确的契约

1. **源码与身份：** 保留精确源码字节和显式节点版本，`.mix` 仍是语义事实来源。记录逻辑资源 ID、格式、尺寸、精确紧密长度与内容完整性。从捕获字节重新计算身份，复用 M6-A 资源摘要及 prepared request 权威性。包字节身份与计划身份分离；对于相同源码/资源/请求，文件名、归档顺序、时间戳和传输元数据不得改变计划。
2. **单次有界装载：** 在 GPU 工作前拒绝不支持的包版本、重复身份、损坏/截断条目、长度不一致、溢出与内容不符。大分配前执行明确的外层字节/数量/元数据限制，并执行全部现有 Core 资源/图限制。定义 Native/browser 的源码、临时传输和最终快照内存核算；不得先无限制整包 JSON 解析或解压，再检查预算。
3. **路径安全：** 运行时装载器只接收字节，不搜索文件系统、不将条目解包到磁盘、不下载 URL。归档候选若有条目名，须指定唯一规范命名空间，拒绝绝对路径、盘符/UNC、反斜杠、`.`/`..`、别名、重名、链接和意外条目。CLI 创作路径是调用方控制的输入，不是资产中的可信运行时路径。不得通过符号链接越界或隐式发现邻接文件。
4. **唯一实现所有者：** Rust 拥有 Native/WASM 共用的包解码和验证，类型化适配层保持轻薄。现有 Core 拥有图语义、准备和资源身份，现有 wgpu 拥有全部像素执行。M6B-02 须在实现前选定 codec 所属模块并以 ADR 说明边界。新增 crate 需要真实依赖/编译边界；本阶段不预授权新增 crate，也不预授权把归档处理放入 Core。
5. **捕获与生命周期：** 保持同步快照及 mutation/destroy/busy 保证。装载器不能形成晚绑定可变资源 ID 或隐藏全局资产缓存。明确包/源码字节、每份解码快照的所有者、分配失败行为及每条错误路径的释放。
6. **兼容性：** 松散 `.mix` 加调用方资源绑定继续可用。外层包版本独立于文档/节点/计划/API 版本。相同解包输入须与松散公共路径产生相同计划身份及像素。M6B-02 显式决定公共 API/包版本；独立维护 PR 已拥有 0.4 候选，不在此预占版本。
7. **请求行为：** 对照 M6-A 切片规则定义完整资源闭包、缺失/未使用/未知 ID 及资源 ID override 行为。不在 JS 重复 Core 遍历，也不隐藏新增 override 歧义。Scalar override 与请求通道仍由调用方提供，不序列化为编辑器状态。

## 工作项与退出门禁

| 工作项 | 交付 | 必需退出证据 |

## 停止与范围规则

若可更简单地满足实测问题、所有权违反架构，或无法证明有界内存，则停止格式选择。不得无证据地抬高现有预算以容纳低效容器。不包含压缩/加密/签名、远程下载、资源缓存/去重、流式子系统、多材质库、`.mix` 图迁移、PNG/JPEG/HDR codec 扩展、特定引擎导出、Studio 修改、新渲染器或发布。压缩及额外格式需要独立实测用例。保留现有全部检查、golden、数值门禁和历史硬件限制。
