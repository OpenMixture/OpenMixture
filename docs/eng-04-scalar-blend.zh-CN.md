# ENG-04 — Scalar 场组合设计

[English](./eng-04-scalar-blend.md) | 简体中文

**状态（2026-09-20）：仅设计。** 本文落实 ENG-01／02 后要求的有界引擎用例、拟议 v1 契约及实现验收计划。`scalar-blend` 尚未注册、可执行或发布。本次不添加着色器、夹具基线、格式迁移或节点。[路线图](../ROADMAP.zh-CN.md)区分本设计与后续实现 PR。

## 用例与决策

引擎消费者需要将独立种子的低频结构场与高频细节场组合为一个高度场，并通过一个公开控件调节。同一图须能通过原生 CLI／Rust 及浏览器 SDK 执行，不依赖 Studio UI 工作。

```text
fractal-noise（seed 11、scale 4、octaves 1）─ a ─┐
                                               scalar-blend ─ value ─ material-output.height
fractal-noise（seed 29、scale 32、octaves 1）─ b ─┘      │
                                                  height-to-normal ─ material-output.normal
constant-color ───────────────────────────────────────────────────── material-output.baseColor
```

暴露 `detailWeight` → `combine.weight`，主要比较请求 height／normal。`weight = 0` 选择低频场，`1` 选择细节场，中间值做插值。这是交叉渐变，不是叠加位移：增加细节时也会减弱低频贡献。如果实际需求是叠加浮雕，应在实现前重新判断用例，不得静默改变本契约。

现有 [blend 契约](../crates/mixture-core/src/nodes/blend.rs)要求 Color `a`／`b` 并返回 Color；[levels](../crates/mixture-core/src/nodes/levels.rs)只能重映射一个 Scalar 输入。当前目录没有 Color-to-Scalar 转换，无法直接用这些节点表达双 Scalar 输出。选择一个专用节点，避免改变 `blend` 端口类型、隐式转换或引入通用数学节点族。本设计不声称已通过像素或人工材质验收。

## 拟议节点契约

| 字段 | 拟议值 |
|---|---|
| 类型／版本 | `scalar-blend`，节点版本 `1` |
| 输入 `a` | 必需 `Scalar`，无默认值 |
| 输入 `b` | 必需 `Scalar`，无默认值 |
| 输出 `value` | `Scalar` |
| 参数 `weight` | `[0, 1]` 内有限 Float，默认 `0.5`，可通过已有绑定机制暴露 |
| 随机性 | 无；上游随机节点仍各自要求显式种子 |
| 采样 | 在当前整数 texel 坐标读取两个输入，不重采样、不访问邻域 |
| 归一化范围 | 将每个有限输入样本钳制到 `[0, 1]`，输出保持 `[0, 1]` |

定义 `a0 = clamp(a.r, 0, 1)`、`b0 = clamp(b.r, 0, 1)`。按照现有编译器约定，将验证后的源权重从 f64 降为 f32。有效 f32 权重为 `0` 时返回 `a0`，为 `1` 时返回 `b0`；否则在 WGSL f32 中计算 `clamp(a0 + (b0 - a0) * weight, 0, 1)`，再对 `(value, 0, 0, 1)` 应用已有 `mixture_half4` 存储约定，写入 rgba16float。端点分支保持精确端点选择，不裁剪源验证，也不引入编译器优化。

有限越界 texel 饱和处理，不做外推。当前公开 Scalar 生产节点已经提供归一化有限值；聚焦着色器测试宿主仍须注入有限越界值验证饱和行为。NaN／无限源参数继续由已有解码／验证拒绝。本设计不承诺清理非有限 GPU 数据，也不通过公开 SDK 接受任意注入纹理。

节点是逐点操作：两个输入具有兼容的平铺边界时保持周期性，但不会修复非周期输入的接缝。不涉及颜色传递函数。高度回读继续采用已有线性 RGBA8 投影，不是半精度中间值的无损表示。中间权重保留已记录的 f32／半精度限制，不承诺跨适配器末位一致。

## 源结构与兼容性

以下片段**仅为示意，当前运行时不支持**；它不是可运行夹具，也不是新文档字段：

```json
{
  "id": "combine",
  "type": "scalar-blend",
  "version": 1,
  "parameters": { "weight": 0.5 }
}
```

将 `low.value` 连接到 `combine.a`、`detail.value` 连接到 `combine.b`，将 `combine.value` 连接到 height 及 height-to-normal。保留已连接的 baseColor 生产节点，因为 v1 material-output 仍要求它。实现 PR 须将完整图及参数变体作为可执行夹具加入，并包含显式噪声种子；本设计不把未实现文档放入已有已接受夹具目录。

这是增量节点类型，`.mix` 文档版本继续为 `1`。已有节点、源字段、默认值和文档行为不变。旧运行时对包含 `scalar-blend` 的文档须返回`MIX_NODE_UNKNOWN_TYPE`；新运行时须通过已有结构化错误拒绝不支持的节点版本及错误端口类型。不允许静默修复图或用 Color 路径近似替代。

拟议编译器增加类型化调用及穷尽 KernelId 映射，对应一个新 WGSL 实现。采用已有单 pass 分配／调度模型，不需要新 crate、JavaScript 语义、缓存策略或序列化框架。明确审查 RenderPlan 调用结构的增量扩展：如果现有结构允许新增且不改变任何旧字节，保留计划版本／哈希域及旧文档哈希快照。如果实现要求修改已有序列化布局、降低规则或资源语义，先停止并单独决定计划版本，再继续。新计划的确定性哈希包含新 kernel／端口及有效权重，仍不包含适配器身份或计时。

增量图类型不代表全面的 Rust 源码兼容。当前公开 `KernelId` 和 `KernelInvocation` 枚举可被穷尽匹配，新增变体可能使下游的穷尽匹配无法编译。实现 PR 必须明确记录该原生 API 影响，选择适当的包／版本政策，并编译使用更新 API 的独立消费者。不得顺手添加 `non_exhaustive` 或重设计公开计划 API。浏览器目录仍由 Rust 元数据驱动，不增加第二套 TypeScript 目录。

显式经审查的注册表预期仅在实现 PR 中从十一种改为十二种类型。十二是结果，不是目标或新的上限。运行时包改变需要新发行版本及验收；已发布 `0.1.0-alpha.0` 不可改写。本设计不授权发行版本或发布动作。

## 实现与验收计划

| 层次 | 实现完成前要求的证据 |
|---|---|
| 核心契约 | 默认值及权重 `0`、`0.5`、`1`；拒绝缺少输入、错误类型、不支持版本、无效／未知参数及越界／非有限权重。验证公开覆盖，包括未使用分支上的无效值。 |
| 编译器 | 源顺序变化和等价默认值下，顺序／序列化／哈希确定；保留分支的有效权重变化改变计划；未使用输出切片剔除该节点；旧哈希快照不变。端点权重仍验证两个输入。 |
| 聚焦 GPU 夹具 | 字面量 `a=0.25`、`b=0.75` 在权重 `0`、`0.5`、`1` 下产生 `0.25`、`0.5`、`0.75`；覆盖相同输入、反向端点、饱和、零／一边界、矩形 `65×3` 及单像素尺寸。使用独立字面预期，不实现 CPU 渲染器。 |
| 真实图 | 确定性的双噪声夹具，权重 `0`、`0.25`、`0.5`、`1`；端点高度字节等于分别渲染的源场，中间结果非退化且对权重具有因果响应。在 1K 检查平铺接触表及高度／法线关系。 |
| Native／浏览器公开消费 | 通过公开 Rust／CLI 和候选浏览器包执行相同夹具、覆盖和通道。记录计划哈希、构建／归档身份、适配器／后端及销毁后自有输出。保留已有精确 checker 和浏览器 v2 门槛；接受新像素前确定聚焦容差。 |
| 回归 | 已有三种材质金图及全部变体不变且通过；注册表预期、节点文档和包声明／目录一致。不得重置已有金图来接受本功能。 |

先做 CPU 契约／计划测试，再做着色器验证、固定软件适配器上的聚焦 GPU 测试、材质评审及 Native／浏览器消费。使用已有命令：`cargo xtask test-core`、`cargo xtask test-plan`、`cargo xtask shader-check`、`cargo xtask golden check` 和 `cargo xtask check`。`cargo xtask test-node scalar-blend` 是**后续实现验收目标，不是今天可用的测试**，只有节点和夹具存在后才有效。将新浏览器夹具执行加入 ENG-03 的独立宿主，不移除保留的 Studio 覆盖。

本有界契约与用例接受后，可以开始实现 PR，不必等待全部历史消费者测试迁移完成。只有按[证据政策](./evidence-policy.zh-CN.md)关联来源明确的执行和视觉证据后，才能关闭实现 PR。设计批准、编译成功和非空像素都不等于材质验收。

## 不在范围内

空间遮罩、混合模式、加法／乘法节点族、有符号／HDR Scalar 域、图改写／pass 融合、图像资源、`.mixpack`、子图、UI 创作、第二像素执行器及已有节点精度变更均排除。性能工作需要实测瓶颈；已知 warp 精度限制独立处理。
