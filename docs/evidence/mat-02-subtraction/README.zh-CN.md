# MAT-02 减法组合反例

[English](./README.md) | 简体中文

这是 [MAT-02 草案](../../mat-02-layered-weathering.zh-CN.md)的有界设计证据，不接受新节点或材质。从干净源码 `4c49186097290a842c0c0f11a9f6a62ad29b229b` 重新构建的 CLI，在记录的 NVIDIA GeForce GT 1030 Vulkan 和 DX12 上复现了反例。既有节点按其半精度契约工作；没有修改旧着色器、容差或 golden。

## 观察

[input.mix](./input.mix)尝试用三个现有节点合成 `max(a-b,0)`：levels 反转 b，以 0.5 权重混合 a 与反转值，再将 [0.5,1] 重映射为 [0,1]。可精确表示的输入为 a=0.5、b=0.499755859375，精确正差为 0.000244140625（1/4096）。第一个中间值将 `1-b` 舍入为 0.5，因此组合结果为零。

最后一个 levels 节点在 RGBA8 编码前把差值放大 4096 倍：渲染的 `height` 像素为 `[0,0,0,255]`。独立常量 `roughness` 参考为 `[255,255,255,255]`，即放大后的解析期望。两个后端均复现这些字节。参考**没有**执行提议的减法内核。不放大时，两者可能量化成同一个 8 位像素，从而隐藏内部值丢失。

[Vulkan 报告](./vulkan.json)、[DX12 报告](./dx12.json)及[回执](./receipt.json)保留精确命令、实际适配器、计划哈希、工具链、二进制／锁文件／验证器身份及输入输出摘要。1x1 像素保留在 `vulkan/` 和 `dx12/` 目录。这证明特定组合限制，不证明任意图精度、可见涂漆金属缺陷、性能目标或未实现节点的正确性。MAT-02a 仍须决定目录准入并冻结材质计划；MAT-01 人工接受继续独立处理。

## 复现与留存

在干净检出中构建 CLI，向留存验证器传入明确二进制、输入及**全新**输出目录：

```powershell
cargo build --locked -p mixture-cli
node docs/evidence/mat-02-subtraction/reproduce.mjs target/debug/mixture.exe docs/evidence/mat-02-subtraction/input.mix tmp/subtraction-new-run
```

若设置了 `CARGO_TARGET_DIR`，须传入实际 CLI 路径。验证器显式执行 Vulkan 与 DX12，拒绝执行期间源码／二进制变化，并独立解码单个 RGBA8 像素。它明确要求两个后端，不在不支持的主机回退。当前源码会产生新记录，不复现原二进制身份。重建原运行时须使用记录的源码修订，并在忽略目录中使用留存输入／验证器字节；这些证据文件是在该修订之后加入的。

Git 保留所选小型输入、报告、回执、像素及验证器的完整内容。报告内原路径描述实际执行，复制后不重写。构建的可执行文件及普通构建日志是临时内容；其摘要不代表永久保留二进制。本次使用开发配置，不作时间性能声明。
