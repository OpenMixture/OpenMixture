# PERF-MAT entry evidence

English | [简体中文](./README.zh-CN.md)

The default painted-metal recipe produces a real budget failure on clean runtime source `e7b25c4e36f6d7a2052fdba11d8cdfffad762a9d` (Rust 0.7.0). The [receipt](./receipt.json) binds the selected input, original reports, all five baseline PNGs and relevant runtime/shader/contract sources. This is an optimization baseline, not MAT-02 material or human PBR acceptance.

The [exact input](./material.mix) resolves the frozen recipe's default controls at reference size 1024. [Its compiled plan](./plan-1024.json) has 23 pixel passes and five connected outputs. The [1K Vulkan render](./render-1024-vulkan.json) on the recorded Windows NVIDIA GeForce GT 1030 succeeds: peak descriptor bytes 201,327,056, live bytes 0, reused bytes 0, and total reported cold time 2,621.9843 ms. CPU-owned output, PNG encoding and driver overhead are not GPU descriptor memory. GPU timestamp duration and warm-render medians were not measured; the report's stage times are wall-clock instrumentation, not hardware GPU timestamps.

The [actual 2K rejection](./rejected-2048.json) reports `MIX_LIMIT_TRANSIENT_BYTES_EXCEEDED` at compile: observed 805,306,832 versus configured 536,870,912 bytes. Both radius overrides are 8, preserving the frozen resolution mapping. No GPU is acquired by `inspect`, no limit is raised, and no 2K pixels exist in this before record. This failure activates the measurement-triggered [PERF-MAT ADR](../../decisions/0009-transient-texture-reuse.md).

Baseline pixels are retained as [baseColor](./baseColor-1024.png), [normal](./normal-1024.png), [roughness](./roughness-1024.png), [metallic](./metallic-1024.png) and [height](./height-1024.png). They are future exact same-adapter before/after comparisons, not installed goldens. BaseColor RGB is sRGB, scalar/normal PNGs are linear. Agent inspection of baseColor shows broad blue paint and exposed substrate with weak rust coloration; it does not close the still-pending material aesthetic, causality, seam or PBR gates. Runtime reuse must preserve these bytes; improving the recipe belongs to material review with separate evidence.

Run `node docs/evidence/perf-mat-before/verify-design.mjs` to verify retained byte hashes, resolve the current frozen default recipe independently and compare it with the retained input, and audit the proposed lowest-free-slot algorithm. Its explicit expected assignment has 14 full-descriptor-compatible slots; the simulated 2K peak is 503,316,944 bytes (480 MiB + 464 bytes). This simulation is CPU graph analysis, not a second pixel renderer or an implemented GPU allocator. The underlying live logical peak is smaller than the total physical pool because slots of different kinds are kept separate.

To reproduce the original runtime at its bound source, build `cargo build --locked -p mixture-cli`, then supply the retained input to the commands in the receipt. At 1024 no overrides are needed; at 2048 use `--set radiusX=8 --set radiusY=8`. After implementation, the original v2 rejection remains historical while a new source-bound record must prove actual pooled execution and unchanged pixels. The original binary, build products and routine logs remain ignored; selected input/reports/pixels are retained here, without an external durable archive claim.
