[English](./m6a-resource-contract.md) | 简体中文

状态：根据用户要求完成 M6A-01，于 2026-09-21 选定设计并提交审查。本文件及 [ADR 0007](./decisions/0007-external-image-resources.zh-CN.md)集成后接受此有界设计，不代表已实现或验收。已发布的 `0.2.0-alpha.0` 无法消费这些资源。M6A-02 至 M6A-05 仍是后续实现与验收任务。下文名称和示例均为计划合同，不是当前可调用 API。

## 用例与节点

将调用方提供的线性高度图与 `fractal-noise`（seed 29、scale 32）通过现有 `scalar-blend@1` 在权重 0、0.25、0.5、1 交叉混合，生成高度和法线。必需的 `material-output.baseColor` 仍由 Color 常量提供。无需 Studio 工作。

仅选定一个新类型 `image-input@1`：无图输入；输出 `value: Scalar`；必需参数 `resourceId`，无默认值。新增真正的参数类型 `resourceRef`，JSON 表示为符合 `[A-Za-z][A-Za-z0-9_-]{0,63}` 的字符串。ID 区分大小写，位于独立的请求资源命名空间中，是逻辑名称，不是路径或 URL。允许通过现有公开参数机制暴露和覆盖；被裁剪分支上的覆盖也须验证语法。不得伪装成 enum 成员。多个节点可以引用同一 ID。

计划中的节点片段（不是当前发行可执行的完整文档）：

```json
{"id":"sourceHeight","type":"image-input","version":1,"parameters":{"resourceId":"heightSource"}}
```

保留 `.mix v1` 外层结构和节点 `parameters` 对象，不增加顶层资源清单、内嵌像素、文件名、URI 或编辑器字段。完整文档验证检查所有节点合同和资源 ID 语法，不要求像素。资源完整性在编译所请求依赖切片时检查。浏览器 `validate` 目前还执行编译，因此继续要求选中资源；原生文档验证及 CLI `validate` 保持仅验证源码。

## 输入表示与像素

每个请求绑定恰好包含 `id`、`width`、`height`、`format`、`bytesPerRow`、`data`。浏览器公开表示为条目数组，以便检测重复 ID；省略表示空数组。Rust 提供等价类型化条目。仅支持 `format: "rgba8-linear"`。`data` 为从左上角开始、按行排列的紧密无符号字节，`bytesPerRow = width * 4`，长度必须恰好为 `bytesPerRow * height`。不接受行填充、尾部字节、像素偏移、多级 mip、图层或负跨度。浏览器 Uint8Array 视图只复制其声明的字节偏移及长度，不复制整个底层缓冲区。

宽高必须为正 u32、满足请求输出尺寸上限，且与请求输出宽高完全相同。浏览器数值必须是有限安全整数，不做强制转换。尺寸不匹配即拒绝，不缩放、不重采样、不隐式转换颜色。G/B/A 可为任意字节且不影响 Scalar，包括 A 为零时；不执行预乘或反预乘。

唯一新增 WGSL 内核从上传的非 sRGB `rgba8unorm` 纹理读取对应整数 texel。Scalar 为归一化 R 值 `R / 255`，通过既有 `mixture_half4` rgba16float 约定存为 `(value, 0, 0, 1)`。无采样器／滤波、垂直翻转或 gamma 转换。保留既有 RGBA8 回读舍入；须测试输入输出的逐字节一致性，不能仅根据半精度中间值假定成立。节点保留输入接缝，不把任意图像修复为周期图。既有环绕 `height-to-normal` 行为继续适用，可能暴露输入边缘不连续。

## 验证、捕获与所有权

1. 验证源码、覆盖及请求元数据；应用覆盖后确定所选依赖切片。按 ID 字典序枚举资源。仅可达图像节点要求绑定存在。判断未知绑定时使用覆盖后所有节点引用的 ID 集，包括未使用分支。
2. 构造映射前拒绝重复 ID；拒绝没有任何节点引用的绑定。已提供但被裁剪的绑定仍检查格式、尺寸、长度和预算，不上传且不进入计划哈希。允许省略被裁剪节点的资源。`scalar-blend` 权重端点仍依赖两个输入。
3. 复制或哈希前检查数量及长度。分配前使用有检查的 u64 运算和宿主长度转换。溢出即拒绝，不回绕、截断或提升上限。资源验证在渲染 GPU 分配／提交前完成；允许已经存在显式初始化的 GPU 上下文。
4. 捕获自有、不可变像素快照。原生准备操作在返回准备请求前同步复制借用字节。浏览器 render 仅接受非共享、不可调整大小的 Uint8Array 存储，拒绝 detached 缓冲区、带访问器及不支持的请求对象；首次异步让出前复制像素和元数据。拒绝 SharedArrayBuffer，不承诺并发写入快照。busy／closing 请求在复制像素前拒绝。调用方随后修改或释放输入不能改变已接受请求。
5. Core 准备不透明且不可变的“编译计划＋所选自有快照”组合，执行器消费该组合；调用方不能替换字节或提供可信摘要。普通 `Renderer::render(plan)` 继续支持无资源计划；有资源计划缺少准备资源时明确拒绝。新增资源公开入口必须支持原生及浏览器消费，无需私有导入。不接受未解析的可执行计划或仅凭 ID 的延迟绑定。
6. wgpu 每次渲染拥有上传及 GPU 纹理；同一选中 ID 即使被多个节点引用也只上传一次。不引入跨渲染资源缓存或内容去重。每次渲染的资源描述符及自有快照在完成、拒绝、GPU 失败或渲染器销毁后释放；输出像素继续独立拥有。原生调用方显式保留准备请求会保留其 CPU 快照，直到主动丢弃。浏览器实例清理后不保留已接受输入。沿用首次错误及 destroy 等待活动渲染的规则。

## 显式预算

为资源请求新增独立的类型化资源限制策略，保留现有 SafetyLimits 及严格解码。省略采用下表默认值；零是有效上限，等于上限通过，不隐式提升。与现有限制一样，u64 策略值在浏览器中使用 bigint。

| 预算 | 默认值 | 计数规则 |
|---|---:|---|
| `resourceCount` | 8 | 捕获前统计全部绑定；重复引用不增加条目 |
| 单轴尺寸 | 既有 `outputDimension`，默认 2048 | 每个输入图像，且必须等于输出尺寸 |
| `resourcePixels` | 16,777,216 | 所有绑定的 width × height 总和 |
| `resourceBytes` | 67,108,864（64 MiB） | 所有绑定紧密字节长度之和，同时限制复制／哈希输入字节 |
| GPU 瞬态字节 | 既有 `transientBytes`，默认 512 MiB | 既有计划／回读／uniform 估计，加所选资源的上传纹理和保守上传暂存估计 |

每个选中资源估计 `4*w*h` GPU 纹理字节及 `align_up(4*w,256)*h` 上传暂存字节，即使实际上传路径需要更少暂存。沿用保守生命周期调度，不引入池化。单独报告唯一上传资源数量、紧密上传字节、资源纹理／暂存估计，与现有输出／pass 计数区分。实际描述符计数须包含新增自有 GPU 分配；估计不声称等于驱动物理分配。

浏览器 JS→WASM 传递期间最多允许两份完整的引擎自有紧密副本，由 `2 * resourceBytes` 约束；Rust 拥有快照后丢弃传递副本。原生准备需要一份自有副本。以上不包含调用方存储、文档／元数据及现有输出缓冲区，是每请求／实例限制，不是跨独立渲染器的全局上限。分配失败须结构化返回，不保证每个策略允许的分配一定成功。

## 身份与兼容性

内部根据捕获字节计算摘要。资源内容摘要为以下字节串拼接后的 SHA-256：UTF-8 `mixture-image-rgba8-linear-v1`、一个零字节、32 位无符号小端 width 和 height、全部紧密 RGBA 字节。保存为小写十六进制。即使节点仅读取 R，也对所有通道哈希，以保守标识精确输入内容。尺寸决定跨度，不信任外部提供的摘要。

计划包含按 ID 字典序排列的所选资源表：ID、format、width、height、bytesPerRow、内容摘要；图像调用引用这些 ID。资源表及上传估计进入规范计划序列化和哈希，原始字节不进入。绑定顺序、无关分支和未使用绑定不改变计划哈希；选中内容、ID、尺寸或引用变化会改变哈希。同名资源替换不得复用旧的可执行资源组合。管线缓存仍按内核／设备 ABI 而非像素摘要索引；新内核增加一个经过审查的缓存身份，不按图像增加缓存项。

| 合同 | 实现时的决策 |
|---|---|
| `.mix` | 保持 v1；在既有源码形状中增加节点／参数类型，不重新解释旧字段 |

| 既有计划哈希 | 有意使 v1 哈希失效，保留旧源码与像素行为。保留 v1 历史回执，新增独立计算的 v2 快照，不重新标注旧验收 |

## 诊断

预留但暂不实现：`MIX_RESOURCE_INVALID_BINDING`、`MIX_RESOURCE_DUPLICATE_ID`、`MIX_RESOURCE_UNKNOWN_ID`、`MIX_RESOURCE_MISSING`、`MIX_RESOURCE_FORMAT_UNSUPPORTED`、`MIX_RESOURCE_SIZE_MISMATCH`、`MIX_RESOURCE_LENGTH_MISMATCH`、`MIX_RESOURCE_IDENTITY_MISMATCH`，以及 `MIX_LIMIT_RESOURCE_COUNT_EXCEEDED`、`MIX_LIMIT_RESOURCE_PIXELS_EXCEEDED`、`MIX_LIMIT_RESOURCE_BYTES_EXCEEDED`。资源请求／身份错误使用 `compile` 阶段；节点参数错误保留既有 `validation` 代码。溢出使用 invalid-binding 并记录运算及操作数。GPU 设备／限制／OOM／执行代码保留首次上传失败，证据增加 operation `resourceUpload` 和资源 ID，不用通用包装替代或隐式回退。

按适用情况包含 nodeId／parameterId、证据中的资源 ID、预期／实际格式／尺寸／长度、配置／实测预算及可操作建议，不记录原始像素。保留确定性诊断排序和原生错误链。浏览器参数／捕获错误沿用结构化请求错误边界；Rust 为语义上可表示的类型化请求提供稳定资源代码。缺失资源诊断按稳定顺序指出每个受影响的可达节点。

实现验收前冻结输入：左上角起始、不对称 2×2 R = [0,64;128,255]，G/B/A 刻意不同；全部 256 个 R 编码；奇数宽度填充陷阱；周期高度块及刻意非周期边缘。要求方向／通道正确、输出有限且在范围内、Scalar 输出 alpha 不透明、字节坡度直接高度往返精确一致；仅修改 G/B/A 时 R 派生像素不变但摘要变化。权重 0 必须等于直接导入高度／法线；权重 1 必须等于直接程序化高度／法线；0.25／0.5 验证因果及非退化。不添加 CPU 图渲染器，通过字面量已知值与代数关系测试生产 shader。

同源码 Native／浏览器高度和法线 RGBA8 对照最大分量差必须 ≤1。不自动把现有材质特定 v2 结构阈值套用到任意输入；使用冻结资源夹具的端点、方向、梯度、接缝保留及因果预期，并审查 1K 高度／法线 contact sheet。既有材质门槛不变。差异须修复或根据证据显式修订合同，不为通过而拟合阈值或覆盖金图。

按变更运行既有 `test-format`、`test-core`、`test-plan`、`shader-check`、`test-consumer`、`gpu-smoke`、`cargo xtask check`。`cargo xtask test-node image-input` 是需要夹具／工具注册的未来目标，本文件未实现。首次验收不需要 CLI 图像加载选项或解码器，使用公开 Rust 消费者和浏览器字节即可。缺少必需资源的 `inspect --plan` 明确失败，不制造占位内容或哈希。

URL 下载、多格式解码框架、颜色／HDR 输入、任意跨度、自动重采样、空间遮罩、加法混合、`.mixpack`、缓存／去重、GPUTexture 导入、零拷贝、新 crate、Studio UI 和发布均不在范围内。下一任务是实现本合同，不是扩展通用资源系统。
