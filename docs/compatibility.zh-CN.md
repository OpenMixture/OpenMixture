## Rust API 与依赖

Core 负责 parse／validate／compile 和无 GPU 诊断。renderer 拥有上下文及管线，接受不可变计划，返回在 renderer／上下文 drop 后仍存活的 CPU 自有像素／报告。不引入隐藏全局设备、备用 renderer 或隐式获取。按[原生 SDK 指南](./native-sdk.zh-CN.md)使用公开方法和类型化错误；私有模块不是消费者 API。

高级上下文 getter 暴露 wgpu 30 的 instance／adapter／device／queue 类型，诊断 limits 暴露 wgpu limits。公开 serde trait 与 `serde_json::Value` 同样暴露依赖类型。这些是已文档化的源码依赖，不是独立不透明 ABI。升级时应重新编译，并审查签名和线上 limits 字段。满足清单版本范围的新依赖不会自动纳入本次验证矩阵。

部分公开枚举为 non-exhaustive，Rust 消费者应按类型要求处理未来变体。诊断反序列化器仍拒绝未知代码字符串。通用 JSON 消费者可保留未知字段／代码字符串用于报告，并明确拒绝不支持的语义；不能静默把未知失败转换为成功。无论消费者如何解码报告，`.mix` 输入仍严格校验。

PR-013 有意新增 `MIX_GPU_DEVICE_LOST` 和 `MIX_GPU_OUT_OF_MEMORY`。`GpuOperationError::reason()` 保留首个分类，附带丢失和分配证据另行提供。替换原生丢失回调会禁用上下文跟踪。类别不透明的获取错误仍为 `MIX_GPU_DEVICE_REQUEST_FAILED`，不根据驱动措辞推断。见 [GPU 失败](./gpu-failures.zh-CN.md)。

## 进程与输出

产品 CLI 退出码仍为：命令完成 `0`，调用／源码／编译错误 `2`，操作失败 `1`。即使带 `--json`，usage 错误仍写 stderr 文本；报告传输失败可能留下不完整 stdout。分离流，并在解析／消费文件前检查进程完成。人类消息、计时值、绝对路径和驱动文本不是可移植快照。

输出为从左上开始、行优先、紧密排列的 RGBA8。颜色 RGB 为 sRGB，alpha 为线性 straight alpha；标量 red 复制到 RGB 且 alpha 不透明；已编码切线空间法线使用线性字节。报告保留所选通道、默认／连接来源及规范通道顺序。不根据文件名猜测编码，不混淆压缩 PNG 字节与原始输出缓冲字节。

PNG 顺序写入而非原子写入：`outputs` 只列完成文件，失败文件可能被部分写入。PR-014 消费者使用新建代次目录和显式清理，令旧请求不写入最新目录。只有最新请求代次可发布；较新失败使保留展示明确过期。消费者限制活跃／待执行工作和输出保留，不为 core 添加运行时调度器。

返回 future 不保证取消。原生 polling 可能阻塞；逐次等待超时不是整体渲染 deadline。消费者取代请求后，已提交 GPU 工作可能仍会完成。逐次描述符预算不包含 CPU 聚合输出、编码、驱动开销和管线内存。九项缓存与 `liveBytes == 0` 是所有权／计数证据，不保证物理 VRAM 立即回收。

## 像素、发布与审查

本轮保持已接受的陶瓷、皮革和木材观感不变。固定 SwiftShader 比较和硬件容差检查覆盖已记录夹具，不保证所有驱动／设备的像素完全一致。shader 或依赖修改需要既有专项测试、适当材质比较和可审查视觉证据。基准更新仍是单独受保护的接受操作，不自动用来修补测试失败。

PR-015 通过隔离消费者验证规范化本地归档内容、精确同组版本及包内资源，不认证注册表发布、二进制安装器或所有原生平台。[包解析](./package-consumption.zh-CN.md)说明有意省略的归档锁、独立固定验证锁及无注册表替代。[发布状态](./release.zh-CN.md)记录 M4 本地及远端验收，以及剩余分发条件与未测试硬件限制。

后续修改前，应识别受影响的源码／节点／计划／报告／Rust 边界，更新最小决定性测试及双语文档，说明兼容性影响与迁移／重编译需求，并记录实现版本。架构改动或新增兼容性承诺仍需既有 ADR 流程。本记录不自动批准下一轮实现计划或扩展节点词汇。
