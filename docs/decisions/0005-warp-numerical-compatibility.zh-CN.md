# ADR 0005：Warp 数值准确性与兼容边界

[English](./0005-warp-numerical-compatibility.md) | 简体中文

**状态：提议中，2026-09-18。** 本文是 ALPHA-03 决策提案，不代表接受 PR #15/#16、更新基准或完成浏览器验收。在明确的接受记录及对应实现审查完成前，现行契约与门槛继续有效。本 PR 不修改架构或路线图不变量。

## 背景

[PR #17 保留的诊断](https://github.com/OpenMixture/OpenMixture/blob/e82372c6867d47810f782efa07c624e419f417bc/docs/evidence/warp-rounding-audit/README.zh-CN.md)区分了两个预先声明的参考：A 从实际 half 输入与 f32 参数出发进行精确有理数运算，最后仅舍入一次到 half；B 模拟指定的逐步 f32 最近偶数舍入、融合插值及最终 half 转换。两者都是诊断模型，不是供挑选的浏览器基准。

从 PR #15 局部坐标到 PR #16 显式插值，软件端全部 41 个变化 warp texel 相对精确 A 都有改善，改后均匹配 A/B。全部 14 个最终 PNG 通道像素差异可追溯到 11 个唯一 warp texel。这支持有限范围内的插值修正，但没有裁决 main 到 PR #15 的全部变化，也不能证明所有输入都改善。新增双重舍入反例在 Native/Chrome/SwiftShader 上均得到 B 的 `0.5`，A 却为 `0.50048828125`；因此显式 `fma` 并不实现普遍的精确实数到 half 正确舍入。

[现有契约](../node-contracts.zh-CN.md)规定标量重复双线性位移、f32 运算和 half 存储，同时描述了绝对 UV 采样计算。局部坐标在实数运算下代数等价，在有限精度下则不等价。必须明确审查这些文档和冻结像素，不能默默宣布旧计算过程无关紧要。[架构第 5、11、16 节](../../ARCHITECTURE.zh-CN.md)区分了版本化含义、实测像素证据和兼容决策。

## 建议决策

继续朝有限范围的 **v1 数值实现修正**推进，前提是完成下述接受步骤。保持场钳制、有符号 UV 强度、输出坐标处读取场、循环寻址、双线性含义、中性场/零强度直接读取恒等、f32 参数转换和 half 存储。以理想重复双线性公式作为准确性目标，同时声明有限精度求值及已记录的适配器覆盖；不承诺每个输入都正确舍入到 A、每个后端都精确执行 B，或跨设备逐位一致。

局部 texel 坐标和显式插值继续作为可独立审查的实现候选。A/B 保持固定的诊断参考：A 测量理想公式误差，B 解释一种运算序列。两者都不替代原软件金图或浏览器同源比较参照；不能逐像素挑选 A/B 来制造通过结果。

[WGSL 浮点规则](https://www.w3.org/TR/2026/CRD-WGSL-20260915/#floating-point-evaluation)允许求值差异，[`fma` 定义](https://www.w3.org/TR/2026/CRD-WGSL-20260915/#fma-builtin)允许非融合实现。改写表达式不是可移植的舍入保证，也不证明编译器缺陷。仅有后端差异不足以向上游认定 bug。

### 各门槛保护什么

| 门槛 | 目的 | 不能证明 |
|---|---|---|
| 节点字面量案例与精确诊断参考 | 位移方向、循环寻址、恒等、插值及局部算术误差 | 全输入域正确舍入或整材质兼容 |
| 冻结的软件适配器 RGBA8 金图 | 检测实现/依赖变化对已接受材质外观的影响 | 每个旧字节都数学正确 |
| 冻结的浏览器逐通道最大/平均/差异比例门槛 | 对固定材质、变体与同源参照约束最终纹理偏移 | 普遍设备支持、WGSL 合规或感知质量保证 |
| 接缝/范围/非有限值/参数因果检查及视觉审查 | 保持材质结构、可用输出与批准的外观 | 字节一致 |
| 源码、包、着色器与适配器身份 | 标识实际测试的可执行内容及消费配置 | 单靠 plan hash 确定像素身份 |

保持所有现有阈值与变体不变。即使标量结果更准确，失败比较也继续记为失败。数学裁决可以支持单独审查的兼容变更，不能把回归失败记录改称通过。

## 替代方案与版本边界

| 方案 | 处置 |
|---|---|
| 保持 main 及冻结像素 | 提案与候选获接受前的现状；保留已知精度限制 |
| v1 实现修正并明确审查像素兼容 | 有条件推荐；不承诺旧缓存图像不变 |
| 将 A 或 B 定义为强制的新数值语义 | 需要独立版本化设计与迁移决策；当前候选没有建立此保证 |
| 同时支持旧、新 warp 版本 | 不是改一行版本号；需显式版本分派、编译映射、内核/缓存身份及消费测试 |
| 现在放宽容差、挑选有利 Native 参照或维护编译器分支 | 证据不足，不在本任务范围 |

如果审查认定文档中的求值顺序本身属于承诺含义，或选择新的强制舍入/顺序契约，则停止 v1 路线。按架构规定，改变该含义需要节点版本与迁移设计；只保持端口与参数不足以证明兼容。也不能反过来要求每个变化像素都自动升级节点版本。

当前[注册表](../../crates/mixture-core/src/registry.rs)按类型 ID 查找单一契约，[验证器](../../crates/mixture-core/src/validation.rs)拒绝其他版本。[Warp 编译映射](../../crates/mixture-core/src/plan.rs)与[内核映射](../../crates/mixture-wgpu/src/kernels.rs)选择唯一的 `KernelId::Warp` 和 WGSL 实现。仅将 `version: 1` 改为 `2` 会拒绝旧文档，并不会保留旧执行方式。并存版本设计必须保持每个 KernelId 对应唯一 WGSL、确定性的计划/哈希身份，并审查当前九内核缓存上限；不得引入第二执行器或静默重写 `.mix`。

## 后果与迁移

推荐路线只有在上述语义审查接受该分类后，才保持源文档、参数含义和节点版本不变。渲染像素及纹理缓存可能变化。需要旧版已接受字节的消费者应保留旧包/构建及其记录环境；本提案不为未测试驱动提供普遍复现保证。应显式重新生成派生纹理并记录构建，像素缓存除 plan 与输出设置外还应包含实现/包身份。Plan hash 标识规范化图语义，不标识着色器字节。

本 PR 不实现源文档迁移或缓存。后续接受记录必须公布新旧源码和归档身份、受影响材质/通道、已审查图像、未变/失败门槛以及缓存/重渲染说明。现有 `golden update <id> --accept` 是审查后的独立显式动作；该标志不等于人工批准证据。在历史记录中保留原金图与失败结果。获接受的新基准必须绑定已批准候选，不能看到浏览器结果后再挑选基准。

## 验证与后续顺序

1. **main → PR #15 兼容证据包。** 解释软件端所有变化的木材输出通道及全部变体，保留前后/差异图。分开坐标变化与插值变化；对未解释的坐标见证沿用 PR #17 同输入诊断方法。记录精确参考误差变差及下游放大情况。PR #17 的 41 texel 结论只覆盖 PR #15 → #16，不能替代本步骤。存在未解释变化就停止接受，不挑选能过的参数。
2. **完成语义决策。** 审查旧采样文字，明确这些等价公式变化是否属于允许的 v1 实现修正；记录解释、数值限制和像素兼容后果。如果选择新含义，先准备独立版本/迁移 ADR 与实现，再改契约。仅有本提案并不授权任何一条路线。
3. **准备候选材质接受。** 保留绑定源码的图像，以及全部三种材质、现有变体的质量/接缝/范围/因果检查和 2K/资源/包检查；继续展示与原基准的比较。先解决兼容与视觉决策，再执行受保护的基准安装；不能削弱受保护 CI 以合入候选。
4. **独立重验普通浏览器。** 固定候选与参照身份后，在普通 Chrome、Edge、Firefox 中安装同一完整包并运行不变的 11 案例/44 通道矩阵，记录实际适配器/后端与版本。PR #16 普通 Chrome 仍为 27/44 通过；Edge 直接字面量及早先 Firefox 结果不能认证该包。用绑定确切源码的新同输入探针调查剩余噪声/皮革/木材路径，不能从旧候选运行推定所有剩余原因。

数值修复可以在实测范围内获接受，而某浏览器仍未通过资格验收；此时不能把该浏览器的 ALPHA-03 标为完成。本提案不会自动产生编译策略、材质基准或支持承诺。

本文档 PR 运行 `cargo xtask links` 和 `cargo xtask check`。运行时接受仍须完成 [AGENTS.md](../../AGENTS.zh-CN.md) 要求的节点/着色器/材质/GPU/消费者检查、视觉证据，以及实际实现版本的远端必需检查。下一项可执行任务是第 1 步，不是继续改写插值。
