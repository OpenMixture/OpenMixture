# ADR 0004：不进行隐式语义回退

[English](./0004-no-implicit-semantic-fallback.md) | 简体中文

状态：M0 基础工程已接受。来源：[架构第 9、12 节](../../ARCHITECTURE.zh-CN.md)。

## 背景

渲染请求必须使用声明的执行模型，或解释为什么失败。隐藏全局状态和回退会掩盖环境错误，并改变输出语义。

## 决策

GPU 获取必须显式进行。调用方拥有的上下文持有 instance、适配器、设备和队列；渲染器拥有的缓存具有明确生命周期。报告包含请求策略和实际适配器／后端。失败返回强类型错误码和阶段，保留驱动证据，不切换到其他语义执行器。

## 备选方案

全局惰性设备会隐藏所有权与初始化失败。自动 GPU-to-CPU 或 WebGL 回退链可能在改变语义的同时报告成功。两者均不接受。

## 影响

使用方必须处理结构化失败。允许 `wgpu` 在显式策略内选择适配器。不引入进程级全局渲染器或缓存。未来 `doctor` 的健康状态声明必须满足 PR 实施计划规定的证据要求。

## 迁移

没有需要保留的回退兼容行为。公共错误术语从 PR-002 开始引入，GPU 上下文和诊断在 M1 跟进。

## 验证

M0 CLI 测试确保未实现操作返回失败，而不是声称成功。M1 在宣布计算／回读健康之前，必须测试缺少适配器的失败情况，并保留请求／所选适配器证据。
