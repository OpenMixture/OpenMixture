# ADR 0007：调用方提供外部图像输入

[English](./0007-external-image-resources.md) | 简体中文

状态：2026-09-21 为 M6A-01 选定并提交审查的设计；此变更集成后接受。实现与 GPU 验收仍待完成。

## 背景

已发布的 0.2.0-alpha.0 可以组合程序化 Scalar 场，但不能消费外部像素。资源输入需要明确请求、所有权、身份及预算合同。ADR 0003 初期将资源交付与文档分离；M6-A 现在需要逻辑引用，同时继续排除交付细节。

## 决策

采用[最小资源合同](../m6a-resource-contract.zh-CN.md)。目录只新增 `image-input@1`，在既有 `.mix v1` parameters 对象中增加真正的 `resourceRef` 参数类型。调用方提供同尺寸、紧密线性 RGBA8 像素，通过唯一 wgpu WGSL 内核把归一化 R 作为高度。Core 负责验证、不可变快照、摘要绑定计划和显式预算；wgpu 负责上传／执行／生命周期；绑定只适配表示。文件、解码、网络、权限仍属于调用方。

这有限取代 ADR 0003 对材质语义中逻辑资源引用的排除，不允许内嵌字节、资源位置、顶层清单或编辑器状态。不改变不变量、依赖方向、crate 边界及唯一执行器规则。实现明确提升计划／哈希至 v2、浏览器 API schema 至 2，以及 1.0 前包的次版本；保留旧文档／像素语义，分发另行决定。

## 备选方案

单个节点参数无需顶层资源字段或 `.mix v2`。伪造 enum 无法描述调用方定义的资源 ID。只对 ID 哈希会错误复用旧内容。延迟可变绑定造成捕获／身份歧义。隐式缩放、颜色转换、下载或打包容器会增加独立语义和安全边界。一边保留所有旧计划哈希，一边引入第二种条件式资源计划模型会增加复杂度，因此选择显式全局 v2 缓存失效。

## 影响与迁移

自有输入副本以有界内存成本保证异步行为确定。同尺寸输入避免采样策略和多分辨率传播。精确字节身份保守地对忽略通道也哈希。旧文档无需迁移，但下游代码须适配新增穷尽枚举／目录类型、schema 2 和变化的计划哈希。v1 回执继续保留为历史，v2 快照独立复算。旧运行时拒绝未知节点。当前已发布包不变，本决策不增加平台或像素支持承诺。

## 验证

M6A-01 运行配对文档／链接检查及 `cargo xtask check`。后续通过公开消费者执行合同中的已知值、资源预算／身份、捕获／生命周期、Native／浏览器及既有材质门槛。保留全部六项必需 CI。合同接受、实现、像素资格及发布分别判断；设计 PR 不修改 shader、夹具基线或包。

## M6A-05 范围补充 — 2026-09-21

[合同范围决策](../m6a-resource-contract.zh-CN.md)将像素验收限定于实测 Linux 软件矩阵。保留的 Windows 失败证据禁止宣称硬件一致性通过；≤1、原着色器语义和全部回归门禁不变。选择有界验收，而非未经审查的数值语义变更或提高容差来贴合结果。更广硬件验收与发布仍需独立决策。
