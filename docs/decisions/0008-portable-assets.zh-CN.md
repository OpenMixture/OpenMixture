# ADR 0008：可选的纯字节可移植资产

[English](./0008-portable-assets.md) | 简体中文

状态：2026-09-22 选定供 M6B-02 评审，集成时接受；运行时实现及验收仍属 M6B-03–05。

## 背景与决定

M6B-01 证明图和邻接像素没有携带离线分发所需绑定。采用[精确 `.mixpack v1` 契约](../m6b-package-format.zh-CN.md)：未压缩规范 USTAR、manifest 在前、精确源码字节和线性 RGBA8 资源，无磁盘解包、网络或可选归档特性。常规/最大内容实测显示 ZIP 节省的少量体积不足以抵消更大验证面；JSON/base64 明显增加体积和临时分配。这是标准归档子集，不是新的二进制图表示。

授权在 M6B-03 增加真实、可选的公共 CPU codec 边界 `mixture-asset`。它依赖 Core 和已有序列化/哈希依赖，由 Native、CLI、WASM 消费；Core/wgpu 不反向依赖。仅使用 Native 源码的消费者保留当前信任/依赖边界。受检规范头解析不需要归档/压缩依赖。资源语义继续归 Core，暴露共用元数据/摘要/引用辅助函数，不把图逻辑移到 codec 或 JS。

## 替代方案

目录 manifest 不满足选定的单制品搬运。JSON/base64 结构简单，但最大内容膨胀约 22 MB 并形成额外解码表示。ZIP stored 可互操作，但须增加中央/本地元数据一致性检查。通用 tar 库支持此纯字节子集之外的文件/解包元数据和扩展。把 codec 放在 CLI 阻碍公共 Native/WASM 复用；放进 Core 扩大每个编译器消费者的归档信任面。实测问题无需自定义二进制格式或压缩。

## 后果、兼容与迁移

新增 crate 的理由是可选编译/公共 API 边界，不是文件数量。窄幅扩展架构以允许 Core 之外的生产者输入资产打包；Core 仍不拥有 ZIP/导出/编辑器打包。`.mix` 保持精确语义来源，松散资源 API 继续有效，等价输入不改变像素或计划身份。显式限制包 v1 的资源 ID override，保留松散 API。独立包/子集上限及保守浏览器缓冲账本由契约定义，不代表总 RSS 或放宽 GPU 预算。

外层包版本 1 和检查 schema 1 独立于不变的 `.mix`/计划/API 版本。实现目标为 0.4 维护候选之后的下一未发布 minor（目前为 0.5），实现前核对版本占用。本设计 PR 不迁移源码、不新增节点或空 crate、不更新锁文件、不发布。

## 验证

留存可复现目录/JSON/ZIP/USTAR 体积及 Python 分配实验、标准工具可读规范 fixture、畸形输入语料、双语文档及 `cargo xtask check`。这验证设计制品，不验证尚不存在的 Rust 装载器。M6B-03 须证明有界分配、恶意输入拒绝、确定性写入、精确源码/资源往返及隔离公共消费；M6B-04/05 补充浏览器生命周期/复制计数、松散/打包计划像素等价及不变的必需 CI/材质门禁。压缩、通用解包或更广归档兼容需要新的有界决策。
