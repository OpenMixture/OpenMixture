# ADR 0010：由调用方提供、由 Core 展开的配方

[English](./0010-reusable-recipes.md) | 简体中文

状态：已接受，2026-10-12 随 [MAT-04a 契约](../mat-04a-recipe-contract.zh-CN.md)经 PR #99 集成。实现与验收仍属 MAT-04b–d。本 ADR 细化 [ADR 0003](./0003-readable-mix-dag.zh-CN.md)；其“一个可读 DAG”的决定对 `.mix v1` 仍然成立。

## 背景

[MAT-04 入口](../mat-04-reusable-recipes.zh-CN.md)测得已验收材质中的重复：砖块和机织物各自在三个图案节点上重复七个控制（各 21 个重复绑定），并在调用方代码中保持相等；遮罩控制的两层表面在三个材质族中被手工重建。`.mix v1` 把每个公开 ID 绑定到一个节点参数，也没有可复用片段。ADR 0003 曾因子图会在缺乏消费者证据时增加编译与迁移复杂度而推迟子图；这一证据现已存在。维护者选定由调用方单独提供的配方文档、仅松散输入、禁止嵌套。

## 决定

- **配方**是独立的严格 JSON 文档（`id@recipeVersion`），包含只用内置节点的图片段，以及由输入、输出和直接赋值参数构成的类型化接口；接口参数可扇出到多个目标。
- **`.mix` v2** 父文档增加 `instances` 数组。v1 不变，仍是现有入口点和 `.mixpack v1` 唯一接受的版本。
- **Core 在规范化之前展开**实例，生成 ID 为 `<实例>--<节点>` 的普通节点。RenderPlan v3、降级、wgpu kernel 和节点目录不变。父图的计划记录 `documentVersion: 2`。
- 调用方以字节形式提供**精确闭包**；Core 拒绝缺失、重复和未使用的配方，绝不解析路径或 URL。配方摘要用于来源报告，不做锁定。
- 配方内每个无默认值的参数（种子）必须绑定到接口，并由每个实例显式设置；不做任何推导。

## 备选方案

- **在父文档中内联定义。** 闭包最简单，但无法跨文件复用，而跨文件复用正是 MAT-04 的既定目标。推迟。
- **在 wgpu、WASM 或 JS 中展开。** 会在 Core 之外复制图语义，违反归属边界。拒绝。
- **把配方作为已编译计划片段。** 需要新的计划版本和执行语义，却没有测得的收益。拒绝。
- **让父图与手写 v1 图哈希相同。** 需要把展开 ID 改名以匹配任意作者 ID，或把 ID 排除在哈希之外，从而改变计划 v3 语义。拒绝；以逐字节相同的像素作为等价门槛。
- **直接在 v1 暴露参数上扇出。** 会重新解释 v1 字段并破坏 v1 唯一性。拒绝。
- **现在就支持嵌套和随包传递。** 没有已验收材质需要它们，且各自都会扩大闭包与上限规则。按维护者方向推迟。

## 后果、兼容性与迁移

现有文档、包、计划、哈希、golden 和回执保持其含义。旧运行时以 `MIX_FORMAT_UNSUPPORTED_VERSION` 拒绝 v2 父图，也不认识 `.mixrecipe` 文档。父图与其替代的 v1 图可能在 pass 顺序、计划哈希和分配估算上不同，但像素相同；冻结预算适用于父图。Core 增加公开配方类型、`RecipeLimits` 和八个诊断代码，因此第一次实现选择 Rust 0.11.0 / browser 0.11.0-alpha.0。不存在自动 v1→v2 转换；作者通过编写 v2 父图主动选用。

## 验证

契约中的冻结门槛：与已验收砖块和机织物图做 CPU 结构等价比较，在记录的适配器上对两个冻结矩阵做逐字节像素比较，冻结预算，控制映射，实例隔离，覆盖每条规则的负面语料，以及 v1 fixture、哈希快照和必需检查保持不变。
