# constant-color v1 fixtures

English | [简体中文](./README.zh-CN.md)

PR-007 [input.mix](./input.mix) and [cases.json](./cases.json) exercise the `constant-color` graph contract. Cases: `defaults`, `lower-bound`, `linear-rgba`. The manifest contains 3 valid GPU cases and 3 invalid source/override cases. Samples are fixed expected RGBA8 sentinels with explicit 0/1-code-value tolerance; they are not generated by a CPU graph evaluator. Invalid cases must fail before GPU acquisition.

ALPHA-03 adds a fourth valid case, `half-storage-boundary`: three f32 values near half `0.232666015625` must export `[133,133,133,255]` after explicit half quantization. The recorded NVIDIA implicit-store path instead exported `[132,132,133,255]`. This regression uses zero tolerance and does not replace an existing golden.

The [contract](../../../docs/node-contracts.md) defines parameters/defaults/formulas; [graph rendering](../../../docs/graph-rendering.md) defines f32/f16 precision, channel encoding, and evidence. The pixel path uses [constant.wgsl](../../../crates/mixture-wgpu/shaders/nodes/constant.wgsl). `material-output` itself only maps resources; synthesized defaults use the constant kernel.

```bash
cargo xtask test-node constant-color
```

This command validates the fixture families without a GPU, then explicitly runs this node on the selected adapter. Local Metal and pinned SwiftShader results are linked from the rendering guide. Pixel goldens remain protected; this fixture command does not update them.
